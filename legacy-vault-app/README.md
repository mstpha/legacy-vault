# Digital Legacy Vault — Mobile App (Sprint 1: Auth only)

A React Native (Expo) app that implements exactly the backend functionality that
exists so far: register, login, TOTP MFA enrollment + verification, session
persistence with auto-refreshing tokens, and logout. No capsule/guarantor/
beneficiary screens yet — those show up as the backend grows in later sprints.

## Prerequisites

- Node.js 20+
- The `legacy-vault-backend` from Sprint 1, **running** (`npm run dev` in that project)
- The [Expo Go](https://expo.dev/go) app on your phone, **or** an Android/iOS simulator
- All commands below assume this project sits next to `legacy-vault-backend` on the same machine

## 1. Install dependencies

```bash
cd legacy-vault-app
npm install
```

Then let Expo align every native package to versions compatible with the installed Expo SDK (recommended — package.json versions here are a good starting point, but Expo updates frequently):

```bash
npx expo install --fix
```

## 2. Point the app at your backend

Open `src/config.js`. By default it targets `http://localhost:4000/api` (iOS
simulator) / `http://10.0.2.2:4000/api` (Android emulator) automatically based
on platform. **If you're testing on a physical phone with Expo Go**, neither
of those works — edit the file and hardcode your computer's LAN IP instead:

```js
export const API_BASE_URL = "http://192.168.1.23:4000/api"; // your machine's IP
```

Find your IP with `ipconfig getifaddr en0` (Mac) or `ipconfig` (Windows, look
for IPv4 Address). Your phone and computer must be on the same Wi-Fi network,
and your backend must be reachable on that network (most OSes allow this by
default on a trusted/home network — no extra config needed on the backend).

## 3. Run it

```bash
npx expo start
```

This opens the Expo dev tools in your terminal/browser:
- Press `i` for the iOS simulator, `a` for the Android emulator
- Or scan the QR code with the **Expo Go** app on your phone

## 4. Try the full flow

1. **Register** — tap "No account yet? Register", fill in name/email/password (10+ chars), submit. You're bounced back to Login.
2. **Log in** — enter the same credentials. Since MFA isn't enabled yet, you land straight on the Home screen.
3. **Enable MFA** — tap "Enable two-factor authentication" on Home. A QR code appears (generated by the backend). Scan it with Google Authenticator/Authy, or type the key shown below it manually. Enter the 6-digit code it produces and confirm.
4. **Log out and log back in** — this time, after entering your password, you're sent to a "Verify code" screen asking for the current 6-digit code from your authenticator app.
5. **Kill and reopen the app** — you should land straight on Home without logging in again: the refresh token (stored via `expo-secure-store`) silently re-establishes the session on launch.

## How the pieces fit together

- **`src/config.js`** — the one place that knows your backend's URL.
- **`src/utils/storage.js`** — wraps `expo-secure-store` so tokens are stored in the device's secure keychain/keystore, never in plain JS state that survives a reload.
- **`src/api/client.js`** — a single axios instance. A request interceptor attaches the current access token; a response interceptor catches `401`s, silently calls `/auth/refresh` once, retries the original request, and — if that also fails — logs the session out.
- **`src/api/auth.api.js`** — one function per backend endpoint (`/auth/register`, `/login`, `/refresh`, `/logout`, `/me`, `/mfa/setup`, `/mfa/confirm`).
- **`src/context/AuthContext.js`** — the only piece of app state that matters this sprint: current user, whether a session is loading/authenticated, and the login/MFA/logout actions. On launch it tries to resume a session from the stored refresh token before rendering any screen.
- **`src/navigation/RootNavigator.js`** — the entire "am I logged in" branch: shows `AuthNavigator` (Login/Register/MfaVerify) or `AppNavigator` (Home/MfaSetup) based on `isAuthenticated`, with a spinner while the session bootstrap runs.

## Troubleshooting

- **"Network request failed" on every screen** → the backend isn't reachable at the URL in `src/config.js`. Confirm `curl http://<that-url>/health` (swap in the same host/port, no `/api`) works from wherever you're running the check.
- **Android emulator can't reach the backend** → double-check you didn't hardcode `localhost` — it must be `10.0.2.2` (the config file does this automatically unless you overrode it in step 2).
- **QR code doesn't scan** → use the manual key shown underneath it instead; any TOTP app accepts a manually-entered secret.
- **Stuck on the loading spinner** → your backend is down or unreachable; the session-bootstrap refresh call is failing silently into a retry loop. Check the backend logs.

## Project structure

```
legacy-vault-app/
├── App.js                        # entry point: AuthProvider + RootNavigator
├── app.json                      # Expo config
├── src/
│   ├── config.js                 # backend base URL
│   ├── api/
│   │   ├── client.js             # axios instance + auth interceptors
│   │   └── auth.api.js           # one function per backend auth endpoint
│   ├── context/
│   │   └── AuthContext.js        # session state + login/MFA/logout actions
│   ├── navigation/
│   │   ├── RootNavigator.js      # auth-gated stack switch
│   │   ├── AuthNavigator.js      # Login, Register, MfaVerify
│   │   └── AppNavigator.js       # Home, MfaSetup
│   ├── screens/
│   │   ├── LoginScreen.js
│   │   ├── RegisterScreen.js
│   │   ├── MfaVerifyScreen.js    # code entry during login
│   │   ├── MfaSetupScreen.js     # QR enrollment, from Home
│   │   └── HomeScreen.js         # profile + logout
│   └── utils/
│       └── storage.js            # expo-secure-store wrapper
```
